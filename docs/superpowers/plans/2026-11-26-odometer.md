# Odometer Implementation Plan

> Execute inline using superpowers:executing-plans, with test-first implementation and a final independent review.

**Goal:** Estimate episode-relative pose from legal observations and validate against real engine movement.

**Architecture:** A packaged, validated calibration feeds a NumPy estimator. DoomAgent updates it from the last returned action. Training-only tooling measures calibration and compares pose with privileged ground truth.

**Tech Stack:** Python 3.13, NumPy, ViZDoom 1.3.3, pytest.

**Spec:** ../specs/2026-11-26-odometer-design.md

## Constraints and review focus

- No privileged runtime inputs or modified policy decisions.
- No fabricated calibration, scripted startup actions, or historical results presented as fresh measurements.
- Preserve checkpoint compatibility and local setup changes outside the PR.
- Cover startup without warmup, opposite/reversed turns, stale action alignment, reset, malformed input, and collision drift.

## Tasks

1. Add real-engine regression tests for pose, heading and calibration validation; run to confirm failure. Implement `Calibration`, `Pose`, `Odometer.reset()` and `update(action, observation)` in `submission/smriti/memory/odometer.py`.
2. Refactor `scripts/measure_odometry.py` to measure startup and use the production estimator for held-out drift. Generate packaged calibration from real measurements; run the script and focused tests.
3. Add failing agent integration tests for initial observation, actual SafetyGuard action bookkeeping, reset and invalid input. Integrate optional pose tracking without changing network inputs or actions.
4. Run regression tests, validator and latency check; review the branch independently, fix substantive findings with regression tests, document measured limitations, commit feature files only, push `feat/odometer`, and open a PR to the fork's main.
